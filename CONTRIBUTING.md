# Как устроен проект и как вносить правки

Планстра существует в двух версиях — русской (`planstra`) и английской
(`planstra-en`). Они **не поддерживаются раздельно**. Английская собирается из
русской, поэтому правку достаточно внести один раз.

## Что где лежит

| Путь | Что это |
|---|---|
| `src/planstra-src.html` | **источник правды.** Здесь и только здесь правится код и тексты |
| `src/build.py` | сборщик: делает обе версии |
| `src/i18n/extract.py` | вытаскивает переводимые строки с точными позициями |
| `src/i18n/en.json` | словарь: русская строка → английская |
| `src/i18n/GLOSSARY.md` | правила перевода и таблица терминов |
| `index.html` | собранный русский сайт (не редактировать руками) |

Английская сборка уезжает в репозиторий `planstra-en` как его `index.html`.

## Как внести правку

```bash
# 1. правим ТОЛЬКО источник
$EDITOR src/planstra-src.html

# 2. собираем обе версии
python3 src/build.py            # → dist/ru/ и dist/en/
```

Если правка добавила новый русский текст, сборка остановится и покажет, каких
строк не хватает в словаре. Допишите их в `src/i18n/en.json` — ключ это русская
строка дословно — и соберите заново.

```bash
# 3. русская версия
cp dist/ru/index.html index.html && git add -A && git commit && git push

# 4. английская — в соседнем репозитории
cp dist/en/index.html ../planstra-en/index.html
cd ../planstra-en && git add -A && git commit && git push
```

## Почему так, а не две копии файла

Копий было бы две, а расходиться они начали бы с первой же правки: поправил в
русской, забыл в английской — и через месяц это разные продукты. Здесь такое
невозможно: английский текст хранится не как файл, а как словарь, и любое
изменение кода попадает в обе версии автоматически.

## Как работает подстановка

Переводы вставляются **по точным позициям в байтах исходника**, а не заменой
строк по всему файлу: одно и то же слово может быть и текстом на экране, и
частью кода, и слепая замена сломала бы второе.

Отсюда два правила, нарушение которых приводит к тихой порче файла:

1. **`extract.py` запускается при каждой сборке.** Любая правка `planstra-src.html`
   сдвигает позиции. `build.py` делает это сам — не отключайте.
2. **Кавычки в переводе экранируются по контексту.** В русском тексте кавычек
   не было (они служат границами фрагмента), поэтому любая кавычка в переводе —
   новая и обязана быть экранирована, иначе закроет строку JavaScript. Этим
   занимается `esc_js` / `esc_html` в `build.py`.

Фигурные скобки `{0}`, `{1}` в словаре — это места, где внутри фразы стоит
HTML-разметка. Их нельзя двигать, терять и переставлять: количество и порядок
должны совпадать с русским оригиналом.

## Чего сборка не делает

Перевод не решает всё. Отдельными заплатками в `build.py` живут:

- **числительные** — русское правило («21 слайд») в английском даёт ошибку,
  там нужно `n === 1 ? "slide" : "slides"`;
- **разделитель дробей** — запятая в русском, точка в английском;
- **выгрузка файла** — в артефакте её делает окружение, в автономной версии
  нужен обычный `<a download>`.

Если добавляете что-то, зависящее от языка не текстом, а логикой, — ему место
там же, в `patch_locale_en`.

## Домены

Один репозиторий на GitHub Pages = один домен. Поэтому версии и разнесены:
`planstra.ru` → `planstra`, `planstra.org` → `planstra-en`.

**Важный порядок действий.** Домен в настройках Pages подключается **после**
того, как DNS начал отвечать адресами GitHub, а не до. Иначе GitHub начнёт
перенаправлять адрес `*.github.io` на домен, который ещё не работает, и сайт
станет недоступен — причём браузеры кэшируют это перенаправление кодом 301
надолго.
